# Style guide

Conventions for code and documentation in this repository. They are enforced by
the gate wherever a tool can check them; the rest are reviewed.

## The gate

A change is complete when this passes, locally and in CI:

```sh
uv run ruff format --check && uv run ruff check && uv run ty check && uv run pytest && uv run beancount-envelope-budget docs --check
```

## Code

- **Ruff** does all linting and formatting (`select = ["ALL"]`). The ignore list
  in `pyproject.toml` is deliberately short, and every entry carries a comment
  saying why it is ignored. Do not add a rule to the ignore list when a local
  `# noqa: CODE` (with a reason) is more honest.
- **ty** must report no errors. A suppression needs a comment explaining why, and
  the Beancount/Fava boundary suppressions are kept in one thin adapter place.
- **Docstrings** are Google-style on every public module, class, function and
  method. Examples in docstrings are doctests, run by `pytest --doctest-modules`,
  so they cannot go stale.
- **Money is `Decimal`**, never `float`.
- **Records are frozen dataclasses with `slots=True`.**
- **Dependency boundaries**: `core.py` imports only `beancount` (plus our
  `schema` and the standard library); `report.py` is pure; only `fava_ext.py`
  imports Fava. Pure code never touches disk. Ledger writes happen only through
  explicit, opt-in surfaces — `pin --write`, the CLI's `--write`, and the Fava
  report's `write` config — and each is a thin writer over the same
  `actions.py` generators. The plugin, CLI and Fava extension are thin adapters
  over `core` and `report`.
- **JavaScript** is one vanilla ESM file (`Envelopes.js`), served directly by
  Fava with no build step, `package.json` or Node in CI. It is presentation only:
  the server still generates and writes every directive, so the report degrades
  to plain forms without it.
- **Coverage floor**: `pytest` fails under 85% on `core.py`.

## Documentation

Two kinds of files live in `docs/`:

| File | Kind | Source of truth |
| --- | --- | --- |
| `cli.md` | generated | the argparse tree; `beancount-envelope-budget docs` |
| `schema.md` | generated | the registries in `schema.py` |
| `errors.md` | generated | the diagnostic registry in `schema.py` |
| `concepts.md` | hand-written | — |
| `style-guide.md` | hand-written | — |
| `original_design.md` | hand-written | — (historical) |

- **Generated files carry a banner** (`> Generated by … Do not edit by hand.`) and
  are checked by `beancount-envelope-budget docs --check`. Never edit them by
  hand; edit the registry or the parser and regenerate.
- **Registries are the source of truth.** Every directive verb, metadata key,
  reserved value and error code lives in `schema.py`. If behaviour and the
  registry disagree, the registry is wrong — fix it there.
- **CLI help is the source of truth** for flag documentation; `docs/cli.md` is
  generated from it. Every command and flag needs help text (a test enforces it).
- **Voice**: concise, second person, present tense. Prefer "moves money from the
  pool" to "money is moved". For errors, always state the fix.
- **Markdown**: ATX headings, one sentence per line is fine, wrap prose near 80
  columns, and use relative links between docs.

## Changelog

`CHANGELOG.md` follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Add an entry under `[Unreleased]` for every user-visible change.

## Commits

Imperative subject line; a body that explains *why*, not just *what*. Keep each
commit to one logical change (one milestone, in this repository's history).
